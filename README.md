# 物品管家

管理三类东西的手机 App，iOS 和安卓共用一套代码（Expo / React Native）。家里用、公司用都可以，第一次打开时选一下，设置里能切换，两边的数据分开记。

- **食品**：扫条码录入，填过期日期（直接选，或按「生产日期 + 保质期」自动算），记库存和每次入库的进价（选填）；快到期、已过期、库存不足时提醒。
- **日用品**：和食品一样扫码录入、记库存和进价、库存不足提醒；过期日期可以不填。
- **设备**：电脑、家电和数码产品。
  - 扫包装盒上的序列号条码录入（登记过的直接打开），同款可「保存并扫下一台」批量登记。
  - 记类别、名称、型号、序列号、数量、购买日期、发票号、保修和随设备的配件；电脑另记芯片 / 内存 / 硬盘（Mac 可点选）。
  - 公司用时登记谁领走、哪天领、哪天还（支持部分退还，留全部领用记录），使用人从员工名单里选；家里用时只记谁在用（从家庭成员里选），保修到期前 30 天提醒。

另外可以定期**盘点**（按实际数量调整库存），看**报表**（进货、消耗、库存和设备统计）并导出成表格。

三类东西都可以分**办公点**管理（家里用时叫「地点」），按办公点导出导入，在手机之间传数据（不需要服务器）。

## 功能说明

- **使用场景**：第一次打开选「家里用」或「公司 / 办公室用」，以后在设置最下面的「通用」里切换。
  - 家庭和办公的数据分开记：物品、批次、出入库记录、设备、领用记录、盘点、地点、人员名单、提醒设置和上次备份时间都各一套，切换后看到的是另一套。报表、盘点、搜索、导入导出都只看当前场景；两边的提醒都照常发。
  - 家里用时「办公点」叫「地点」，第一个地点叫「家」；设备不登记领用、退还，改记「谁在用」、购买日期和保修，保修到期前 30 天提醒；提醒页的「借出设备」换成「快过保」；盘点设备时数一共有几件（谁在用的也算）。
  - 从只有一套数据的旧版本升级上来时，原来的数据原样留在升级前的那个场景里，另一个场景从空的开始。
- **扫码**：认识的条码直接打开该物品，选「入库」或「出库 / 用掉」；没见过的条码进新建页，并去 Open Food Facts 开放商品库查名称（只发送条码；国产商品收录不全，查不到就手填，手填一次后本机就记住了）。
- **拍照识别（安卓 1.9.0 起）**：
  - 入库时「过期日期」「生产日期」旁边点「拍日期」，用小取景框拍瓶盖、封口、袋边上的喷码：认出一个日期直接填；写着「生产」「保质期至 / EXP」的直接分好；认出几个分不清时把拍到的那一小块放上面，列出来点选；商品有保质期时按生产日期算出到期日，和喷码上的到期日对上了会提示。
  - 新增物品时，扫码后本机没有这个条码（商品库也没查到），条码下面出现「拍包装识别」：先拍背面标签，标签上写「见瓶盖」时接着拍喷码（可以跳过），也能从相册选。认出的名称、规格、保质期、生产日期填进去，格子浅蓝底标「识别」，没认出的标「没认出来」，名称拿不准时列出「也可能是」；核对完点「保存」才保存。
  - 拍得不好（糊、暗、反光，或者什么都没认出来）时提示重拍。认不准的留空，不会乱填。
  - 识别全在手机上：PaddleOCR 的 PP-OCRv6_small 模型（ONNX Runtime 推理）打在安装包里，不联网；照片识别完就删，不上传、不进备份。
  - 需要安卓 8.0 以上。Expo Go 里没有（自己写的原生模块），按钮不显示；iOS 以后做。
- **保质期**：物品资料里可以记保质期（如 12 个月），新建时用「生产日期 + 保质期」填的、拍包装认出的会记下来，也能在「编辑」里改；有保质期的物品入库时默认按「生产日期 + 保质期」算到期日，只要选或拍生产日期。
- **出入库**：物品详情页点「入库」「出库 / 用掉」，扫已录过的条码会直接打开它。同一商品买了好几次、过期日期不同，会分批记录。出库时选原因（用掉、过期丢弃、坏了、送人、其他），可以填备注；数量最多到现有数，到了上限「+」变灰。默认先扣最早到期的那批，有两批以上时可以在「从哪一批出」里自己选，每一批都能点 − / +。
- **进价**：入库时可以填单价和总价，都是选填（建议填）。填了单价按数量自动算总价，填了总价按数量自动算单价，改数量时另一个跟着重新算。单价按入库时选的单位算（按箱入库就是每箱的价，单位从瓶换成箱时单价跟着换算，如每瓶 2 → 每箱 48）。每次入库的价格单独记在那条入库记录上，以后价格变了不影响以前的记录；同一物品再入库时单价默认填上一次的价（按这次的单位换算），可以直接改；新建物品时的「这次入库」也能填。详情页「信息」里显示上次进价。价格只记数字，不带货币符号。
- **整箱进、按个出**：每个物品按「最小单位」（瓶、个、包…）记库存，可以另设包装规格，如「1 箱 = 24 瓶」「1 提 = 6 瓶」。入库、出库时都能选按箱、按提还是按瓶填，自动换算；库存显示成「50 瓶（2 箱 2 瓶）」。整箱外包装上的条码可以录到对应的包装规格里，扫箱子会直接认出这个物品，并默认按箱入库。库存下限按最小单位填。
- **出入库记录**：每次入库、出库、手动改批次都记一条流水（时间、数量变化、原因；按箱进出的会注明「按 2 箱」；入库填了价格的会显示单价和总价），在物品详情页查看。
- **提醒**（设置页可改）：
  - 到期前几天开始提醒（默认 7 天；单个物品可另设）
  - 多久提醒一次：每天 / 每 2 天 / 每 3 天 / 每周（到期当天一定提醒）
  - 每天几点提醒（默认 09:00）
  - 库存下限：库存 ≤ 下限时提醒补货（每个物品单独设，留空不提醒）
  - 家里用时，设备保修到期前 30 天那天也提醒一次（跟着「到期提醒」开关）
  - 家庭、办公两个场景的提醒都发，各用自己的提醒设置；同一天同一时刻两边都有，合成一条通知，分别用「家里：」「公司：」开头；时间不同各发各的。
  - 用的是手机本地通知，不需要服务器；每次打开 App 或改库存都会按最新数据重排未来的提醒（每个场景最多先排 28 条物品提醒、2 条备份提醒）。
- **提醒页**：汇总已过期、快到期、库存不足和借出中的设备（家里用时是保修快到期的设备），点进去直接处理。上方有「盘点」「报表」两个入口。
- **盘点**：
  - 开始时选办公点和范围（食品、日用品、设备，默认食品和日用品）；同一办公点同时只能有一次进行中的盘点，已有时可以「接着盘那一次」。
  - 逐项清点：点一行填实盘数量（可按箱或按瓶），「和账面一样」一键保存，也能「改回未盘」；可扫物品条码、包装条码或设备序列号直接定位，也能按名称、条码、序列号搜；筛选全部 / 未盘 / 有差异。数量随填随存，离开后回来接着盘。
  - 「完成盘点」后按「实盘 − 清点时的账面」调整库存，清点之后又入库出库的不受影响：盘亏先扣最早到期的批次，盘多了并到最早到期的那一批（没有批次就新建一批）；每项记一条「调整」出入库记录，备注写「盘点：账面 10，实盘 8」。没盘的不调整。完成后不能撤销。
  - 设备公司用时盘在库数量（总数减借出），家里用时盘一共有几件（谁在用的也算）；只记差异，不自动改数量，丢失或报废要到设备里手动处理。
  - 可以「放弃这次盘点」，库存不变，盘点单留在历史里；已完成的盘点能查看结果和差异，导出 CSV。
- **报表**：
  - 按办公点（可看全部）和时间段（本月、上月、近 3 个月、今年）看。进货、消耗、物品明细按时间段统计，库存概况和设备是当前情况。
  - 库存概况：食品、日用品各几种，库存不足 / 快到期 / 已过期，点开看名单。
  - 进货：金额合计、入库次数、按分类的金额、金额前 10；没填价格的入库不算进金额，会注明次数。
  - 消耗：按出库原因的次数、用得最多的前 10；「过期丢弃」「坏了」单独列出，按出库前最近一次进价估算损失，没有进价的不算进合计。
  - 物品明细：每个物品这段时间的入库、出库、现有数量和进货金额（盘点调整不算在入库、出库里）。
  - 设备：总数、借出、在库及按类别统计，保修 30 天内到期和已过保，领用排行（家里用时没有借出、在库和领用排行）。
  - 导出三个 CSV 表格（出入库明细、当前库存、设备清单），Excel / WPS / Numbers 能直接打开，通过系统分享发出去；家里用时设备清单没有借出、在库两列，「使用人」叫「谁在用」。
- **导入导出**（设置页「数据」里点进去）：
  - 只导出、导入当前场景的数据，另一个场景不动。
  - 导出：生成一个备份文件 `item-keeper-backup-日期-时间.json`，包含当前场景的全部物品、包装规格、批次、出入库记录（含入库的单价、总价）、设备（含发票号、芯片、内存、硬盘）、领用记录、人员名单（含部门、邮箱）和提醒设置，文件里记着是在哪个场景导出的，通过系统分享存到「文件」、网盘或发给自己。
  - 导入：选一个备份文件，先整份校验（哪条数据哪个字段不对会直接说出来，不会导入一半），确认后替换当前场景现有的数据。文件是在另一个场景导出的，会先问一句要不要导入到现在的场景，确认后照常导入，不会切换场景。
  - 按分类：导出时可以只勾食品、日用品、设备、设置里的几类；导入时也只替换勾选的分类，没勾的原样保留（会先检查导进来的条码和保留下来的物品有没有重复）。人员名单和部门跟着设备走：导入勾了设备时先按名称合并部门，再按姓名合并人员（没有的加上，有的用文件里的部门、邮箱、备注更新；本机多出来的部门和人都不删）。
  - 新手机导入：本机只有一个还没放东西的默认地点（「默认办公点」或「家」）、文件里又没有它时，直接换成文件里的地点，不会多出一个空地点。
  - 撤销：导入前会自动把当前场景的数据留一份，导错了可以在导入导出页「撤销上次导入」，只换回当前场景的数据（部门和名单也换回导入前的）。
  - 备份提醒：超过 N 天（默认 60，设置里可改，0 为不提醒）没完整导出（分类、办公点都全选，按钮显示「导出全部」），提醒页显示「该备份了」并发通知，之后每 7 天一次；家庭、办公各算各的，上次备份时间只记在本机，不随备份文件走。
  - 盘点记录不进备份文件，只存在这台手机上；盘点产生的库存调整是出入库记录，会随备份带走。
- **办公点**（设置页「通用」里管理，家里用时叫「地点」）：每样东西属于一个办公点；有多个办公点时各页右上角切换或看全部；条码在同一办公点内唯一。
- **人员名单**（设置页「通用」里管理，公司用时叫「员工名单」，家里用时叫「家庭成员」，两个场景各一份）：
  - 公司用时加人依次填部门（点选已有的部门，或者点「+ 新部门」当场建一个；可以不选）、姓名、邮箱（选填）和备注（选填）；家里用时只填姓名和备注。姓名最多 20 个字，不能重名（不分大小写）；邮箱要像邮箱，存成小写，名单里别人已经用了的不让保存。
  - 员工名单按部门分组显示，每组写部门名和人数，没有部门的放在最后一组「未分部门」；每人一行，姓名下面是邮箱和备注。点开一个人可以改部门、姓名、邮箱、备注，或者删除。
  - 「管理部门」里新建、改名、删除部门，能看到各部门有几个人。部门名最多 20 个字，不能重名（不分大小写）；改名后名单里跟着显示新名字；删除部门时里面的人变成「未分部门」，人员和领用记录都不删。从旧版本升级上来的人都在「未分部门」，以前写在备注里的部门不会自动拆出来。
  - 登记领用、修改领用记录（家里用时是「谁在用」）时，使用人输入框下面列出名单里的人，点一下就填上；输入时按姓名、部门、邮箱或备注过滤（家里用时按姓名或备注）。名单还是空的时列最近用过的名字。名单外的人也能直接手填，这时可以勾「同时加到员工名单（家庭成员）」（默认勾上），保存时一起加进名单（没有部门，以后在名单里补）。
  - 改名时，领用记录里写着原来名字的一起改成新名字（会先说有几条）；删除只从名单里删，已有的领用记录不动。
- **手机互传**：导出时选办公点和分类，用聊天软件、隔空投送、快传发给别的手机；对方导入时只替换本机对应办公点的对应分类，办公点按名称对应，本机没有就新建。约定每个办公点由一台手机负责记账，就不会冲突。
- **数量和日期输入**：所有数量框都可以直接输入或点 − / +，只接受数字；有上限的（比如出库最多到现有数）到了上限「+」变灰，输多了直接提示。日期、时间点开是滚轮选择。
- **手势**：列表里点开看详情、长按编辑；向左滑时这一行不动，红色「删除」从右边滑出来盖住右侧的数量，名称和标签照常显示，点「删除」就删（底部 5 秒内可撤销）；滑开后点这一行或向右滑收回，同一时间只有一行滑开。五个标签页可以左右滑动切换。
- **定位起名**：添加或改名办公点时，可以用当前位置反查地名给出候选名字（系统查不到时用 OpenStreetMap）。
- **数据**：存在手机本地 SQLite 里，不经过服务器；家庭、办公各一个数据库文件。盘点记录也只在本机，不进备份。

## 在手机上试用（不用装 Xcode / Android Studio）

1. 手机装 **Expo Go**（App Store / Google Play 搜 “Expo Go”）。
2. 电脑上：
   ```bash
   cd ~/code/item-keeper
   npm install
   npx expo start                  # 手机和电脑在同一 Wi-Fi
   npx expo start --tunnel ngrok   # 不在同一网络时用这个（要先 npm i -g @expo/ngrok）
   ```
3. iPhone 用相机扫终端里的二维码，安卓用 Expo Go 扫，就能打开。

扫码、本地通知、SQLite 在 Expo Go 里都能用；拍照识别要用打出来的安装包。

## 打成安装包

**安卓（本机打，不需要账号）**：装好 JDK 和 Android SDK 后运行 `scripts/build-android.sh`（脚本开头写了要装哪些），产物在 `dist/item-keeper-<版本>.apk`。用的是调试签名，只适合自己装，不能上架。拍照识别的模型（约 30 MB）不在仓库里，脚本会先跑 `scripts/fetch-ocr-models.sh` 下载并校验 sha256（放在 `modules/label-ocr/models/`，下过的不再下）。

**iOS** 给同事日常用走 **TestFlight**：苹果官方的测试渠道，开发者账号上传后，同事用 TestFlight 这个 App 安装，自己人（内部测试员）测试不用审核；每个版本 90 天后过期，要重新上传。临时试用也可以用 Expo Go（见上一节）。

上传 TestFlight 时注意：
- 每次上传前把 `app.json` 的 `ios.buildNumber` 加 1（同一个版本号下构建号不能重复）。
- 包名 `com.itemkeeper.app` 不要改，并且一直用同一个开发者账号上传。这样同事装新版本时是覆盖更新，数据保留；换了包名或账号会变成另一个 App，旧数据带不过去。
- 版本过期后 App 打不开，但数据还在手机上，装上新上传的版本就能接着用（别让同事先删 App）。
- 从 Expo Go 换到 TestFlight 版，数据不会自动过去，要在 Expo Go 里导出、TestFlight 版里导入。

用 EAS 云端构建（安卓 / iOS 都行，本机不需要 Xcode / Android Studio，需要一个免费的 Expo 账号）：

```bash
npx eas-cli@latest login
npx eas-cli@latest build:configure          # 首次会问 iOS bundle id / 安卓包名
npx eas-cli@latest build -p android --profile preview   # 出 apk，直接发给别人装
npx eas-cli@latest build -p ios --profile production     # 需要 Apple 开发者账号
npx eas-cli@latest submit -p ios                         # 上传到 App Store Connect，在 TestFlight 里加测试员
```

## 开发

```bash
npm run typecheck   # TypeScript 检查
npm run lint        # ESLint
npm test            # 单元测试 + 用 Node 自带 SQLite 跑真实迁移和读写的数据层测试
```

目录：

```
src/app/            页面（expo-router，文件即路由）
  (tabs)/           底部五个标签：提醒、食品、日用品、设备、设置
  scan.tsx          扫码页
  stock/            食品 / 日用品的新建、详情（入库出库）、编辑
  device/           设备的新建、详情（领用退还；家里用时是谁在用）、编辑
  stocktake/        盘点列表、盘点单与结果
  report.tsx        报表与导出表格
  backup.tsx        导入导出
  offices.tsx       办公点（地点）管理
  people.tsx        人员名单（员工名单 / 家庭成员）管理
src/db/             SQLite 表结构与查询（两个场景各一个库，外加一个记场景和库对应关系的小库）
```

## 目前的限制

- 数据只在一台手机上；多人 / 多设备共用需要加服务端同步。
- 导入是整份替换，不做两份数据的合并。
- 国产商品条码联网查名经常查不到，需要手填一次；如果要查得全，可以接中国物品编码中心等付费接口。
